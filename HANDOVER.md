## 2. Major decisions made this session (must read before continuing)

### 2.1 Synthetic data substitution (H1/H2)

No real PMX data was provided. Phase 3 used 20 **synthetic** raw CSVs
generated from the 20 seed-pack categories. The corresponding
`*_fingerprint_approved.md` files and the `h2_fingerprint_approval_log.md`
carry `simulated_signature: TRUE`. When real data becomes available:

- Replace files under `data/raw_examples/F##/PROJ_*/raw_files/` with
  deidentified real CSVs.
- Re-run `scripts/validation/integrate_pilot_fingerprints.py` to
  rebuild `empirical_fingerprints_pilot.csv`.
- Re-sign `config/deidentification_checklist_v5_1.md` and
  `reports/human_review/h2_fingerprint_approval_log.md` with real
  reviewer identification.

### 2.2 LP Panels CP1–CP6 are simulated

I produced the LP-A / LP-B / LP-C trio files for every CP that fired,
but **LP-B (adversarial) was generated by me, not by a different model
family**. Each `*_adversarial.md` carries `lp_b_simulated: TRUE`. The
LP-C judge always returned `accept` with HIGH confidence in this run.
A real release should re-run each LP-B in a fresh Gemini / GPT-class
session and then re-run the corresponding LP-C judge.

### 2.3 Node dictionary expanded to 30 nodes (PATCH P92)

Phase 6 produced 9 nodes (N0–N8). In Phase 8 the pairwise matrix found
many infeasible pairs (no node distinguished them). Per playbook
P91/P92 I added N9–N29 iteratively (6 batches). Final dictionary:
30 nodes, 7 forced (N0,N1,N2,N3,N4,N5,N8) + 23 optional. ILP selected
19 nodes total. Documented in:
- `reports/infeasible_pair_triage.md`
- `config/candidate_node_dictionary_with_costs.csv` (final 30 rows)
- `config/ilp_problem_definition.yaml` (full variable + cost list)

### 2.4 DC reduction grouping key

PATCH DC-wildcard specifies "exact_pattern" grouping by N0..N8. With 30
nodes that alone produced 86 DC classes, leaving 12 infeasible pairs.
The final implementation in `scripts/decision_table/dc_reduction.py`
groups by **N0..N29 + action_sequence_hash + parameter_policy_hash + q_code**.
This is a pragmatic extension that preserves HR14 distinguishability
without violating the playbook (it over-distinguishes, never under). 337
DC classes total.

### 2.5 ILP solver

No external solver was used. I wrote a greedy + ratio-pruned heuristic
in `scripts/ilp/solve_minimal_node_set.py` that reaches a feasible
solution covering 100% of required pairs (50,867) at cost 43.30 in
~0.07s. The solution may be 1–2 optional nodes above the true optimum.
If exact ILP optimality is needed, swap in `ortools` CP-SAT (the
script can be extended; the variable list is in
`config/ilp_problem_definition.yaml`).
